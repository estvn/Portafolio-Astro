## Resumen

PokeQueue es una aplicación base desplegada en Azure que genera reportes en CSV de forma asíncrona: una UI en Next.js, una API en FastAPI, una base de datos SQL Server, Blob Storage para los archivos y una Azure Function (Python) que procesa los reportes en segundo plano. El proyecto consistió en extenderla con nuevas funcionalidades sin romper su despliegue.

## Logros clave

- <strong>Eliminación completa de reportes</strong> (UI con modal de confirmación, endpoint DELETE, procedimiento almacenado con borrado lógico y borrado del CSV en Blob Storage).
- <strong>Reportes enriquecidos</strong>: el worker serverless consulta PokeAPI por cada Pokémon y agrega hp, ataque, defensa, ataque especial, defensa especial, velocidad y habilidades al CSV.
- <strong>Reportes con muestreo</strong>: el usuario define cuántos registros desea, y el valor viaja por la UI, la API, la base de datos y el worker.
- Cambios coordinados en cinco repositorios (UI, API, serverless, base de datos e infraestructura).

## Stack

Next.js / React, FastAPI (Python), Azure Functions, Azure Blob Storage, SQL Server, Docker, Terraform.

### Backend (FastAPI)

- Se ha creado un Endpoint de la API que recibe una solicitud HTTP con el método DELETE con el ID del elemento a eliminar.
- Este Endpoint desencadena una serie de acciones:

Procedimiento almacenado para eliminar reportes:

```
ALTER PROCEDURE pokequeue.delete_poke_request(@id int)
AS
SET NOCOUNT ON;
BEGIN

UPDATE pokequeue.[requests]
	SET [active] = 0
where id = @id AND [active] != 0;

IF @@ROWCOUNT > 0
	SELECT 1 AS response;
ELSE
	SELECT 0 AS response;

END;

EXEC pokequeue.delete_poke_request 70;
```

## Overview

PokeQueue is a base application deployed on Azure that generates CSV reports asynchronously: a Next.js UI, a FastAPI API, a SQL Server database, Blob Storage for the files and an Azure Function (Python) that processes reports in the background. The project consisted of extending it with new features without breaking its deployment.

## Key achievements

- <strong>Full report deletion</strong> (UI with a confirmation modal, DELETE endpoint, stored procedure with soft delete and removal of the CSV from Blob Storage).
- <strong>Enriched reports</strong>: the serverless worker queries PokeAPI for each Pokémon and adds hp, attack, defense, special attack, special defense, speed and abilities to the CSV.
- <strong>Sampled reports</strong>: the user chooses how many records they want, and the value travels through the UI, the API, the database and the worker.
- Coordinated changes across five repositories (UI, API, serverless, database and infrastructure).

## Stack

Next.js / React, FastAPI (Python), Azure Functions, Azure Blob Storage, SQL Server, Docker, Terraform.

### Backend (FastAPI)

- An API endpoint was created that receives an HTTP DELETE request with the ID of the item to delete.
- This endpoint triggers a series of actions:
	- First, it checks whether the item is already "deleted in the database". If it is, it returns a 404 status; if it is not "deleted", it is removed from the database.
	- Once the item is deleted from the database, it deletes the CSV file from the BLOB Storage, and once that is done the endpoint response is sent.
